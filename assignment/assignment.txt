You will build an event-driven automation using the Devin API that solves a concrete engineering workflow problem. You should present your solution as if pitching Devin to a VP of Engineering, alongside senior engineers who will evaluate your technical depth.
 
We are intentionally evaluating how you:
Translate ambiguous problems into working systems
Leverage Devin as a core primitive (not just a helper tool)
Communicate both technical execution and business impact
 
 
The Challenge
Part 1: Select a Use Case
The engineering team is working on the following repository:
https://github.com/apache/superset
Clone or fork the repository into your own organization
Identify and create issues in your fork that you intend to remediate as part of this project
(e.g., vulnerability findings, dependency upgrades, code quality issues)
 
 
Part 2: Build an Event-Driven Automation
Using the Devin API:
https://docs.devin.ai/api-reference/overview
Build a working automation that remediates the issues you created. Your system should:
Be triggered by an event
(e.g., webhook, repository activity, ticket creation, scan results, or a scheduled/periodic trigger)
Programmatically initiate and manage Devin sessions
Produce observable outputs for a technical audience
(e.g., pull requests, issues, reports, status updates)
 
 
Part 3: Incorporate Observability
Your solution should include basic analytics or reporting to demonstrate system effectiveness. This may include:
Status of active and completed tasks
Success/failure signals
Throughput or progress tracking
This can be simple (e.g., logs, lightweight metrics), but should clearly answer:
"If I were an engineering leader, how would I know this is working?"
 
 
Deliverables
1. Working Project
A working system where Devin successfully remediates the selected issues.
 
 
2. Loom Video (5 minutes MAX)
Present your solution to a technical audience (VP of Engineering + senior ICs) who are curious about Devin.
Your video should cover:
What: Problem framing — what workflow problem are you solving, and why does it matter?
How: Demo the system in action and show how Devin is working behind the scenes. Walk through the key architectural decisions in your code.
Why: Make the case for why Devin is uniquely suited here — what can this system do that wouldn't be possible (or practical) without an autonomous coding agent?
When: Next steps — how would you extend this in a real customer engagement?
 
 
3. GitHub Repositories
Provide:
A GitHub repository containing your solution (use Docker)
Include a clear README with instructions to run or simulate the workflow
A forked or copied version of the Apache Superset repository
Include the issues you selected and remediated
